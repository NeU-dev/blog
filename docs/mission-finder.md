# ミッション・ファインダー

好きなこと1つ・嫌いなこと1つを、選択25問＋自由記述3回で深く掘って、ミッションの下書きをつくるツール。記事の中に埋め込んで使う。

## 質問の流れ

| 段 | 問い | 中身 |
|---|---|---|
| 好きを掘る | A1〜A8 | 惹かれるところ・満たされる瞬間（全員）→ 掘る問い5問（型はAIが選ぶ）→ 続けている理由 |
| 自由記述1 | FT1 | 好きなことで忘れられない場面（問いはAIが答えに合わせて書く） |
| 嫌いを掘る | B1〜B8 | 何がイヤか・代わりにどうなってほしいか（全員）→ 掘る問い6問（型はAIが選ぶ） |
| 自由記述2 | FT2 | 嫌いなことで許せなかった場面（同上） |
| つなぐ | C1・C2 | 好きと嫌いに共通しているもの（AIが両方の答えから仮説を書く）・最後の見極め |
| 相手など | D1〜D4 | 誰のために・方向性・関わり方・距離 |
| ミッション | E1〜E3 | 根っこの気持ち → 候補 → 言い直し |
| 自由記述3 | FT3 | 自分の言葉で一文に |

掘る問いの型（`generator/template.js` の `PROBES`）：なぜ（一段上の理由）・もう一段なぜ（大事にしている価値）・失ったら・例外・勧めるなら・きっかけ・見極め（好き側）／なぜ・もう一段なぜ・誰が困っているか・例外・どうしがちか・変えられるなら・見極め（嫌い側）。
型ごとに測る気持ちの枠は決まっているので、どの型の組み合わせになっても集計は同じやり方でできる（「選択肢として出た回数」で割ってそろえる）。
AIが使えないときは `DEFAULT_ORDER` の順番で聞く。一度出した型は保存して固定する（戻っても問いが変わらない）。

## 記事に置く

置きたい場所に、1行だけ書く。

```md
::mission-finder
```

記事ページのスクリプト（`src/layouts/PostLayout.astro`）が、この枠を見つけたときだけツールを読み込む。

## 結果画面

- ミッションは2つまで。1つ目は本人が最後に書いた文。2つ目は「好きと嫌いをつなぐ気持ち」（C1の答え）の候補を下書きとして出し、結果画面で自分の言葉に書き換えられる（1つ目と同じ気持ちなら、次に強い気持ちから）。
- 「あなたの言葉から」：AIが、書き上げたミッションと本人の好き・嫌い・文章のつながりを読み解く（AIが使えないときは出さない）。
- 「好きと嫌いを掘ったら」：好き（惹かれるところ → 満たされる瞬間 → 手に入れているもの → 大事にしていること）と、嫌い（イヤなところ → 損なわれているもの → 見過ごせない理由 → 代わりにほしい状態）の2本の流れと、2つに共通していること。
- 「PDFで保存」：結果をA4の紙面にして画面の外で画像にし、PDFファイルとしてそのままダウンロードさせる（`pdf.js`）。文字も画像で入るので日本語フォントを埋め込まない。画像にするライブラリ（html2canvas-pro）は押したときにだけ読み込む。長いときは、ブロックの切れ目でページを分ける。

## AIを有効にする（公開の手順）

AIの関数を公開するまでは、ツールはテンプレート版で動く（壊れない）。

1. 回数制限のマイグレーションを当てる（Supabase の SQL Editor で実行してもよい）

   ```bash
   supabase db push
   ```

2. APIキーを secret に入れる

   ```bash
   supabase secrets set ANTHROPIC_API_KEY=（あなたのキー）
   ```

3. 関数を公開する（neulog-community と同じく、ログインなしで呼べるようにする）

   ```bash
   supabase functions deploy neulog-mission --no-verify-jwt
   ```

### 調整できる secret

| 名前 | 既定 | 内容 |
|---|---|---|
| `MISSION_MODEL` | `claude-haiku-5-5` | 使うモデル。文言の質を上げたいなら `claude-sonnet-5-5` など |
| `MISSION_VISITOR_DAILY_LIMIT` | `30` | 1人あたり1日のAI呼び出し回数（1回の利用でおよそ11回） |
| `MISSION_DAILY_LIMIT` | `800` | サイト全体の1日のAI呼び出し回数（およそ70人ぶん） |
| `MISSION_AI_ENABLED` | （なし） | `false` にするとAIを止め、全員テンプレート版になる |

1回通したときのAI呼び出し（およそ11回）：選択肢の言い換え2回、掘る問いの計画2回、その場の問い3回（好き・嫌いの「もう一段なぜ」と、つなぐ問い）、自由記述の読み取り2回、ミッション候補1回、結果の読み解き1回。実際の金額は Anthropic Console の使用量で確かめる。

上限を超えると、画面に一度だけお知らせを出して、定型の選択肢で続ける。

## 進み具合を数える

何人が、どの問いまで進んだかだけを数える。答えの中身（好き・嫌い・選んだ選択肢・自由記述・ミッション）は送らない。

- 画面は、前の問いへ進んだとき（戻ったときは送らない）と、PDF保存・コピーをしたときに、`neulog-mission?action=progress` へ `{ run, step, ai, event }` だけを送る。`run` は1回の利用ごとの乱数で、「やり直す」で新しくなる
- 関数は、訪問者のハッシュ（回数制限と同じもの）と一緒に、いちばん先まで進んだ問い・PDF保存・コピーだけを `neulog_mission_runs` に残す。1人1時間200回まで
- 集計は `neulog-mission?action=funnel`（`x-neulog-dashboard` ヘッダーに `DASHBOARD_ACCESS_KEY`）。ブログエディタの「アクティビティ」の下に、問いごとの人数と、いちばん多く止まった問いが出る
- 人数は、同じ人が何回やっても、いちばん先まで進んだ回で1人と数える
- 開発中は、`?mission-ai=local` で手元の関数につないだときだけ送る
- 問いの並びを `flow.js` で変えたら、`progress.ts` の `PROGRESS_STEPS` も合わせる（`progress_test.ts` が照らし合わせる）

## 手元で試す

`npm run dev` で記事を開き、URL に次を付ける（開発中だけ効く）。

| パラメータ | 動き |
|---|---|
| `?mission-ai=mock` | 偽のAIで、言い換え・掘る問いの計画（型の順番がテンプレと変わる）・その場の問い・引用つき分析・ミッション候補・読み解き・相談先の表示を試す |
| `?mission-ai=mock-limit` | 「今日の上限に達した」状態を試す |
| `?mission-ai=off` | AIなし（テンプレート版） |
| `?mission-ai=local` | 手元で動かしたAIの関数（localhost:8000）につなぐ。下の「本物のAIを手元で試す」 |
| `?mission-debug` | 結果画面にスコアと回答データを出す |

### 本物のAIを手元で試す（公開せずに）

1. `supabase/functions/.env` を作り、1行だけ書く（`.gitignore` の `.env` で Git には入らない）

   ```
   ANTHROPIC_API_KEY=（Anthropic Console で発行したキー）
   ```

2. 関数を手元で起動する（回数制限なしの手元モード）

   ```bash
   MISSION_LOCAL=1 deno run --no-lock --node-modules-dir=none --allow-net --allow-env --allow-read --env-file=supabase/functions/.env supabase/functions/neulog-mission/index.ts
   ```

3. `npm run dev` の記事を `?mission-ai=local` 付きで開く

キーを書き換えたら、関数を起動し直す（キーは起動時に読む）。

入力画面の「サンプルを入れる」も開発中だけ出る。

関数のチェックとテスト：

```bash
deno test --no-lock supabase/functions/neulog-mission/validate_test.ts
deno check --no-lock --node-modules-dir=none supabase/functions/neulog-mission/index.ts
```

## AIの使い方の決まりごと

- 「何を測るか」「全部で何問か」「集計（どの気持ちが強いか）」はAIに任せない。AIが受け持つのは、次の問いの型を選ぶことと、文を書くこと。
  1. 選択肢の文言：動機コードの枠（スロット）を固定したまま、本人の好き・嫌いに合わせて言い換える。その項目に合わない枠はこじつけない。足りない枠はテンプレ文言で埋める。
  2. 掘る問いの計画：最初の問いの答えと、まだ見分けがついていない気持ちを見て、メニューから型を選んで並べ、問いと選択肢を書く。「なぜ」は必ず入れる、「もう一段なぜ」は「なぜ」のあと、見極めは2回まで、ほかは1回まで（崩れていたら画面側で直す）。続く自由記述の問いも、このとき書く。
  3. その場の問い：「もう一段なぜ」は直前の答えを受けて、つなぐ問いは好き・嫌いの両方の答えから書く。
  4. 自由記述の読み取り：本人の文章からの引用つき。引用が本文に無いものは捨てる。本人が言っていること（testimony）だけをスコアに入れ、推測（inference）は表示だけ。
  5. ミッション候補（E2）と言い直し案（E3）：集計で決めた気持ちごとに、本人の言葉を入れた短い一文（「〜こと」で終わる）を書く。もとにした本人の言葉も添え、本文に無い引用は捨てる。
  6. 結果の読み解き・作れそうなもの・最初の一歩・次の問い。
- AIが使えないとき・失敗したときは、どれもテンプレ文にもどる（ツールは止まらない）。
- 自殺・自傷・虐待などが読み取れたら、先へ進む前に相談先を出す。
